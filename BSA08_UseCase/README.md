# BSA08_UseCase — Варианты использования (Use Cases)

Детализация требований через сценарии взаимодействия пользователей с 
системой. Use Case описывает, *как именно* система будет выполнять 
пользовательскую историю.

## Exercise 00 — Описание вариантов использования (Менеджер)

[src/ex00_BBS_UC.md](./src/ex00_BBS_UC.md)

Use Case (Вариант использования) — это описание того, как актор (роль) 
взаимодействует с системой для достижения своей цели. Он включает в себя 
предусловия, триггер, основной сценарий и постусловия.

Задание учит отделять цель актора от действий системы. Менеджер хочет 
«настроить расписание», а система для этого выполняет ряд действий 
(проверяет данные, сохраняет изменения). Этот артефакт — прямой мост 
от бизнес-требований к техническому заданию.

## Exercise 01 — Описание потоков вариантов использования (Менеджер)

[src/ex01_BBS_UC.md](./src/ex01_BBS_UC.md)

Описание потоков (Flows) — это пошаговый сценарий. Он делится на основной 
(happy path) и альтернативные (исключения). Все шаги пишутся в формате 
«Актор/Система — Действие».

Задание учит описывать взаимодействие без технических деталей (без кода 
и SQL), используя язык бизнеса. Важно минимизировать развилки, вынося 
сложные проверки в отдельные альтернативные потоки, чтобы основной 
сценарий оставался читаемым.

## Exercise 02 — Описание вариантов использования (Клиент)

[src/ex02_BBS_UC.md](./src/ex02_BBS_UC.md)

Расширение списка UC для Клиента. Здесь появляется важный кейс: 
возможность записаться без регистрации. Это не просто отдельный UC, 
а **расширение (extend)** основного сценария записи.

Задание учит видеть необязательные (опциональные) сценарии. Клиент может 
записаться как авторизованным, так и нет. Связь `extend` позволяет 
не перегружать основной сценарий, описывая специфику незарегистрированных 
пользователей отдельно.

## Exercise 03 — Описание потоков вариантов использования (Клиент)

[src/ex03_BBS_UC.md](./src/ex03_BBS_UC.md)

Детализация потоков для Клиента с учетом расширения. Показано, как 
основной сценарий прерывается на расширение (ввод номера телефона), 
если клиент не авторизован.

Задание учит правильно связывать основной и расширяющий сценарии. 
В альтернативном сценарии (3.а.2) клиент возвращается к нужному шагу 
основного сценария, а не к началу — это критически важно для 
проектирования пользовательского интерфейса и логики системы.

## Exercise 04 — Описание вариантов использования (Мастер)

[src/ex04_BBS_UC.md](./src/ex04_BBS_UC.md)

Описание UC для Мастера (просмотр расписания и отзывов). Здесь также 
применяется связь `extend` — мастер может не просто прочитать отзыв, 
но и ответить на него (UC-MST-03).

Задание учит выделять опциональные действия в отдельные UC. Ответ на 
отзыв не является обязательным для просмотра, поэтому он выносится 
в расширение. Это делает систему гибкой и понятной.

## Exercise 05 — Описание потоков вариантов использования (Мастер)

[src/ex05_BBS_UC.md](./src/ex05_BBS_UC.md)

Пошаговое описание сценариев Мастера. Включает в себя основной поток 
просмотра расписания и расширение для ответа на отзыв.

Задание закрепляет навык описания потоков. Обрати внимание, что при 
возникновении ошибок вывода данных (альтернативный сценарий) система 
уведомляет пользователя и предлагает вернуться к началу.

## Связь с другими блоками

Use Cases опираются на User Stories (BSA07) и бизнес-процессы (BSA06). 
Они описывают *что* делает система, но не *как* она устроена внутри. 
Детализация объектов, их атрибутов и прав доступа к ним будет в 
следующих блоках (BSA09, BSA10).
