# BSA09_Objects and Roles — Сущности и диаграмма классов

Описание структуры данных на уровне объектов и их взаимосвязей. 
Переход от логической модели данных (ER) к объектно-ориентированной 
модели (UML).

Описание сущностей в табличном виде — это детализация модели данных. 
Для каждого объекта определяются атрибуты, их типы, обязательность, 
значения по умолчанию и ограничения.

Задание учит детально прорабатывать структуру данных. Например, класс 
«Персоны» выносится в отдельную сущность для хранения общих данных 
(логин, пароль, ФИО), от которой наследуются «Клиенты» и «Сотрудники». 
Это позволяет избежать дублирования данных и обеспечивает целостность.

## Exercise 04 — Создание диаграммы классов

[src/ex04_BBS_ClassDiagram.png](./src/ex04_BBS_ClassDiagram.png)

Диаграмма классов (UML) — это визуальное представление объектной модели. 
Она показывает классы, их атрибуты и связи между ними (наследование, 
ассоциации, агрегация).

Задание учит мыслить объектами, а не просто таблицами. Наследование 
(например, Клиенты и Сотрудники наследуют Персон) позволяет переиспользовать 
код и данные. Ассоциативные сущности (Услуги мастера) решают проблему 
связи «многие ко многим» (M:N).

## Связь с другими блоками

Диаграмма классов опирается на ER-модель (BSA04) и детализирует её 
с точки зрения объектно-ориентированного подхода. В дальнейшем эти 
сущности и их статусы будут использованы в FR Design (BSA10) для 
описания жизненных циклов и прав доступа.
